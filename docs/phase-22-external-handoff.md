# Phase 22 — External Integration Handoff & Final Verification

The project is **functionally complete for everything that can be built inside this
repository.** Every user-facing workflow, the AI system, the Bewerbung Scanner, the
email engine + worker contract, billing/entitlements (fail-closed), item-level erasure,
storage reconciliation, rate limiting, security headers/CSP, GDPR export/deletion, and
the deployment readiness gate are implemented and passing.

The **only** remaining work is external: it requires credentials, products/prices,
hosting, or production configuration that cannot be provisioned from within the
repository. Each external seam below is intentionally left **clean and inert** — no
invented credentials, no fake providers, no fake prices.

Run `npm run check:env` before deploying: it now reports an **external integration
seams** section (Phase 21) that flags exactly which of the items below are still
pending, from in-repo state alone.

## 2. Operator runbook (deterministic)

1. **Environment**: set all `.env.example` vars → `npm run check:env` (must exit 0).
2. **Web app**: `npm run build` + deploy any Node ≥ 22 host.
3. **Monitor**: `GET /api/health` (public, `no-store`) → `{ status, checks: { database, workerSecretConfigured } }`; `200` when the DB is reachable, `503` otherwise. Booleans only.
4. **Email worker**: run **any** durable poller: loop `POST /api/internal/email-worker/claim` (returns the next due campaign, or no-op) → send via the connected provider → `POST /api/internal/email-worker` to finalize each message. Header `x-email-worker-secret: $EMAIL_WORKER_SECRET`. A single poller is correct; multiple are safe (`FOR UPDATE SKIP LOCKED`).
5. **Storage janitor**: on a low-frequency cadence (e.g. hourly), `POST /api/internal/storage-reconcile` (same secret). Start with the default **dry-run** body `{}`; review the report; then enable `execute: true` once it matches expectations.

## 3. Final verification (Phase 22)

All of the following were verified in this final pass; evidence is the passing test
suite plus the static review of the flagged code paths.

1. **Security hardening** — auth before every sensitive operation (`getCurrentUserAndProfile` / `auth.getUser()` / `x-email-worker-secret`); rate limits preserved on all abuse-sensitive endpoints.
2. **Authorization / RLS / cross-user** — every user-owned read/write is scoped by the authenticated user id; ownership asserted server-side before destructive operations; admin actions actor-scoped; RLS enabled and `auth.uid()`-scoped; internal RPCs service-role-only (revoked from `public`/`anon`/`authenticated`).
3. **Data integrity** — FK/cascade/RESTRICT contracts honored; row-before-storage deletion; orphan cleanup path-prefixed and idempotent.
4. **Deletion / privacy** — item-level erasure + full GDPR deletion (drafts → auth cascade → path-prefixed storage sweep; aborts before storage on DB failure); OAuth tokens/credentials structurally excluded from export.
5. **AI / email / scanner workflows** — quota enforced plan-aware and atomic; file/conversation/generated-file lifecycle + cleanup; scan create/own/delete/bulk-delete.
6. **Billing / entitlements** — FREE/PLUS/PRO resolved server-side from persisted state; **fail-closed to FREE** on any lookup failure; no client-supplied plan; no prices/credentials invented.
7. **Worker / reconciliation** — secret-gated; deterministic 401/400/no-op failure; stale-campaign recovery and storage janitor self-healing.
8. **Environment / deployment readiness** — `check-env` gate (Phase 20) + external-seams report (Phase 21); names-only, exit codes correct.
9. **Error handling & leakage** — user-facing routes return controlled messages; DB/constraint/provider details are not surfaced. **Fixed in this phase:** `createBlankDraft` previously rethrew a raw Supabase `insert` error (reachable from the composer server action) — now collapsed to a fixed message (see `tests/application-drafts.test.ts`). Auth/OAuth surfaces retain Supabase's own controlled user-facing messages (intentional, not infrastructure leaks).
10. **External dependencies** — documented above; nothing internally-completable is left open.
